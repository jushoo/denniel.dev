# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add dark mode (system default + light/dark/system toggle) to the Astro portfolio with no flash of wrong theme.

**Architecture:** Semantic color tokens in `@theme` are overridden under `html[data-theme]` selectors — Tailwind v4 utilities reference the CSS variables, so the whole site switches with zero component changes. A tiny inline `<head>` script resolves the theme before paint; a header icon button cycles preference.

**Tech Stack:** Astro 7, Tailwind CSS 4 (v4 `@theme` variables), vanilla inline scripts. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-30-dark-mode-design.md`

**Testing note:** This repo has no unit test framework. Verification is `astro build` plus manual dev-server checks specified in the final task.

### Task 2: No-flash theme init script in Layout.astro

**Files:**
- Modify: `src/layouts/Layout.astro`

- [ ] **Step 1: Add inline script to `<head>`**

Inside `<head>`, immediately after the `<meta charset>` line (must run before first paint), add:

```astro
<script is:inline>
  (function () {
    var theme = 'system';
    try {
      var stored = localStorage.getItem('theme');
      if (stored === 'light' || stored === 'dark' || stored === 'system') {
        theme = stored;
      }
    } catch (e) {
      /* storage unavailable — keep system */
    }
    document.documentElement.dataset.theme = theme;
  })();
</script>
```

Note: no JS color-scheme handling — Task 1's CSS sets `color-scheme` per `data-theme` and follows OS changes automatically via the media query.

- [ ] **Step 2: Add toggle script**

At the end of the file, after the `</header>` tag, add:

```astro
<script>
  type Theme = 'light' | 'dark' | 'system';
  const order: Theme[] = ['light', 'dark', 'system'];
  const storageKey = 'theme';

  const root = document.documentElement;
  const button = document.getElementById('theme-toggle') as HTMLButtonElement;
  const icons = button.querySelectorAll<HTMLElement>('[data-theme-icon]');

  function storedTheme(): Theme {
    try {
      const value = localStorage.getItem(storageKey);
      if (value === 'light' || value === 'dark' || value === 'system') return value;
    } catch {
      /* storage unavailable */
    }
    return 'system';
  }

  function apply(theme: Theme): void {
    root.dataset.theme = theme;
    for (const icon of icons) {
      icon.classList.toggle('hidden', icon.dataset.themeIcon !== theme);
    }
    button.setAttribute('aria-label', `Theme: ${theme}`);
  }

  apply(storedTheme());

  button.addEventListener('click', () => {
    const next = order[(order.indexOf(storedTheme()) + 1) % order.length];
    try {
      localStorage.setItem(storageKey, next);
    } catch {
      /* keep in-memory theme; nothing to persist */
    }
    apply(next);
  });
</script>
```

Note: no `matchMedia` change listener is needed — Task 1's CSS media query makes `system` follow live OS switches for colors and `color-scheme`; the icon stays the monitor while in system mode. (Same behavior as spec; achieved purely in CSS.)
